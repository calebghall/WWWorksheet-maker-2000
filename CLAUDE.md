# World Wide Worksheet Maker 2000: working notes for Claude sessions

Printable elementary-math worksheet generator with answer keys. Output is one self-contained HTML file (no libraries), also deployed to GitHub Pages. Read `notes/worksheet-maker-2000.md` for the user-facing feature list; this file covers how the code is organized.

## Commands
- `python3 build.py` builds `WWWorksheet-maker-2000.html` from `src/`: one single file with the coin images embedded. The tests read this file. Never edit the built file.
- `python3 build.py --target site` writes `dist/` for GitHub Pages: `index.html`, `assets/coins/*.jpg` (loaded by relative path; `coin-paths.js` replaces the embedded `coin-images.js`) and `standards/<fw>.<hash>.js` (frameworks that are not embedded) and `.nojekyll`. `--embed tn,ky|none` picks the standards frameworks registered inside the page (default `tn`). `dist/` is not committed. `.github/workflows/pages.yml` builds, tests and deploys it on every push to `main`.
- `./tests/run_tests.sh` builds, then runs all checks (about 100,000 generated problems verified independently, flow-packing invariants and a density comparison against the grid (`logic-mix.js`), a layout clipping sweep including every Number Sense type, a combined-sheet check, `logic-gap.js` (Number Sense answers recomputed from each problem's own fields), `logic-standards.js` (every preset renders and stays within its digit limits), `logic-vis.js` (Shapes, Measures and Data types recomputed from their own fields), `logic-g3.js` (the grade 3 types), `logic-setcodes.js` (set codes still produce the same worksheets), `logic-parts.js` (parts, part presets, Mixed from parts, saved parts), `parts_ui.py` (the parts panel in a browser), `std_ui.py` (standards panel: full text, multi-select), `logic-typemap.js` (type map, tags), `logic-strands.js` (strand modules, legacy-state, parts and preset migration, mixability), `types_ui.py` (type groups, search and the all-standards entry in a browser), `site-check.js` (the Pages build: relative coin files, nothing embedded), page errors). Run it after every change.
- All paths in the Pages build must be relative (no leading `/`): a project site is served under `/repo-name/`.

## Other folders
`assets/coins/` (the 256 px coin JPGs, served on the site), `tools/` (coin image generator), `tests/` (all checks, `standards.json` source data), `notes/` (`worksheet-maker-2000.md` feature list, `generators.md`, `standards-coverage.md` and `coverage/<fw>.md`, `next-modules.md`); `standards/` (per framework `<fw>.json` import, `<fw>.annotations.json`, `<fw>.crosswalk.json` standard to preset ids; `standards/dist/` is generated), `.github/workflows/pages.yml` (deploy).

## Module contract
`REG.<id> = { name, counts, n0, [on0:false], plan(st, n, seed) }`.
`plan` returns `{ sub, probs, cols, rowH, gap, cls, style, cell(problem, number, isKey) }`. Cell-based modules just call `arithPlan(st, id, problems)`. The combined worksheet needs nothing else. A section with rows of varying height returns the row-based form described under Conventions instead.

## Adding a module: touch points outside the module's own file
1. `js/core/config.js`: add to `MODULES`.
2. `js/core/ui.js`: `defaults()` (settings and title; `ns` and `vis` type defaults come from the registry), `normalize()` (clamp saved values), `writeForm()`, `readForm()`, and any note text.
3. `html/<id>.html` plus an include line in `src/index.html`: fieldsets with `data-mod="<id>"`.
4. `js/core/render.js`: branch in `generateSet`.
5. `js/core/cellkit.js`: add the id to `CELL_MODS`, a branch in `modHtml` (`tm` delegates to `tmHtml` in its own file; `ns` cells come from `NHTML` and `vis` cells from `visHtml`, both filled by the registry); `js/core/layout.js` `arSub` if the subtitle should differ.
6. Add checks: independent answer verification in `tests/` (see `logic-fdp-ns.js`), and include the module in `tests/clip.py`.
7. Update `notes/worksheet-maker-2000.md`.

## Conventions and gotchas
- Mixed Practice is both a standalone module (`st.module === 'mix'`, flow pages) and a Combined Worksheet section (`REG.mix`). Its section plan is row-based: it returns `flowRows` (each with its own height), `gap`, `fs` and `flowHtml(fromRow, toRow, startNumber, key)` instead of `cols`/`rowH`/`cell`, and `comboPages` splits it by row height. Topic checkboxes (`st.mix.mods`) are shared by both uses. Problem size hints (`needSize`) drive packing, trimmed by the measured table `FLOW_FIT` in `mix.js` (hint-to-real-size ratios; re-measure and update it if a cell's rendering changes); a hint that is too small causes clipping, too large wastes space.
- Problems are deterministic from the set code (`seed`) and settings. Never use `Math.random` in generators; use the passed `rng`.
- Each problem has `mod`, `type`, `prompt`, `sig` (dedupe key) and size hints `ew`/`eh` in em (or `win`/`hin` in inches). Wrong hints cause clipping, which `tests/clip.py` detects.
- Sheets are laid out in inches (`PAPER`); body height is `P.h - 2.22` for combined sheets, and the `@page` rule matches the paper size.
- The vertical multiplication sum line appears only on the answer key for multi-digit multipliers.
- Mixed Practice reads `mixPartsOf(st)`: the parts that use a mixable topic (`MIX_MODS`), or one equal part per checked topic. A part's `n` is a weight there and an exact count in Combined. Parts that use `vis` or `area` stay in Combined and are left out of Mixed.
- Parts (`st.parts`, `core/parts.js`): the first part of a module keeps the seed `seed|id` that an unsplit Combined section always used, later parts of that module use `seed|id|k`, so existing set codes are unchanged. Generators must keep reading their settings from the `st` they are given (never a global) so a part can run with its own. A new module needs an entry in `PART_KEY`, `applyModSettings` and `captureSettings`. `tests/logic-setcodes.js` compares hashes of rendered sheets (every module, Combined, Mixed and every preset) with `tests/golden-sets.json`; when an output change is intended, announce it and run `node tests/logic-setcodes.js --update`. `md.alt` stays in the generator and `normalize` so saved settings keep their sheets; the 4.NBT.B.5 preset uses two parts instead.
- Known refactor candidates: per-module defaults/readForm still live in `ui.js` (the clamps moved to `clampMod` in `parts.js`); a module could own them via a `REG.<id>.settings` hook.
- Sandbox blocks Google Fonts; the console error is harmless.
- Adding a problem type: write the generator `(rng, level)` and the cell body `(p, key, x)` in the family file it belongs to (or start a new `ns-*.js` / `vis-*.js` file and add it to `src/index.html`), and register it in that file's `defTypes` call with `id`, `label`, `blurb`, `on` and `gen`/`html`. The registry supplies the checkbox, the default and the generator tables; nothing in `ui.js` or the panel html needs editing. Add a check in the matching `tests/logic-*.js`. Types are organized by worksheet type; standards mappings are data only (`standards.js`, `standards/<fw>.crosswalk.json`, `notes/coverage/`): to support a standard, add a preset naming existing type ids and a level (a `n` note makes it Partial), point the standard's crosswalk row at it, then run `python3 build.py` and `node tests/coverage.js`. Keep standard codes and grade names out of generator files. Wide word-problem cells set `wide: true` (class `wq`).
- Number-line cells size their height with the type size (`hfs` in `modNeed`); a fixed hint clipped in the combined sheet at 14 to 15 pt.
- The `<!--@include css/...-->` lines inside `<style>` in `src/index.html` show a CSS lint warning in VS Code. It is harmless: `build.py` replaces them before the page is parsed.

## Colors and greyscale print

- Drawings never hard-code category colors. Use `VFILL[i]` (`--c0` to `--c3`) and the other palette tokens defined in `css/base.css` (`--c1d`, `--c3l`, `--tip`, `--wood`, `--ruler`, `--cu`, `--ag`, ...).
- The "Greyscale print" option (`state.grey`) adds class `grey` to `#sheets`. The `.sheets.grey` rule in `base.css` replaces every token with a neutral grey; the four category greys differ by about 15% lightness so categories stay distinguishable on a black and white printer. Do not use a CSS `filter`: pastel colors collapse to near-identical greys, and filters rasterize print output.
- A new token needs a value in `:root` and in `.sheets.grey`. `tests/logic-grey.js` checks grey spacing, that grey tokens are defined in `:root`, and that every coin has both image copies, stays under 22 KB, and is referenced rather than repeated.

## Repeated problems

- Every generator returns a `sig` naming everything that is visible; the sheet builder drops problems whose `sig` it already has. A `sig` that includes hidden randomness (shuffled option order, an unseen rotation) lets visual repeats through, so build it only from what is printed. `tests/logic-dups.js` fails when two problems look identical but have different sigs, and when a default-settings sheet of up to 36 problems repeats.
- `notes/generators.md` lists each generator in one line and marks types with a small pool of different problems.
